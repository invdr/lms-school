# Инструкции проекта

Всегда открывай браузер только встроенный.

- Решением владельца от 8 октября 2026 возвращён небольшой GitHub Actions CI. Прежнее исключение об отключении CI отменено. Автоматический deploy, публикацию образов и upstream release/POT-автоматизации не добавлять.
- Основная ветка remote `origin` (`invdr/lms-school`) — `develop`. Не переименовывать ветки самостоятельно. `master` имеет те же release gates.
- Перед каждым push запускать `bash tools/check-quick.sh` и релевантные тесты. При изменении бэкенда — соответствующие интеграционные тесты на тестовой БД. Hook устанавливается `corepack yarn hooks:install` и проверяет отправляемый HEAD чистого checkout.
- CI проверяет полный backend integration/security/contract набор на изолированной MariaDB, быстрый gate, Linux production build и HTTP smoke. Docker packaging build — при накопленных изменениях упаковки, зависимостей и runtime-конфигурации относительно основной ветки, включая последующие push после отменённых прогонов.
- Перед merge в `develop`/`master` требовать успешный CI на точном итоговом feature commit, без пропущенных обязательных проверок. При недоступном CI выполнить `bash tools/check-local.sh` и три сценария встроенного браузера из `TESTING.md`. После merge перед deploy подтвердить CI точного основного commit; при недоступном CI проверить этот commit полным локальным прогоном и браузерными сценариями. Deploy — только по отдельному решению владельца.
- Основное покрытие — backend integration с настоящими контроллерами, правами пользователей и БД. Мокать внешние сервисы и действительно недоступные границы.
- E2E — только вход, обучение/сохранение прогресса и сохранение курса: короткие независимые сценарии без фиксированных задержек, CSS-классов и длинной настройки через UI.
- Unit/contract-тесты — для безопасности, сложной логики, внешних границ и важных клиентских регрессий без дешёвого интеграционного покрытия. Сохранять деньги, транзакции, concurrency, идемпотентность и recovery. Не добавлять заглушки, проверки исходного текста, стилей, формулировок или копии реализации в моках.
- Тесты с изменением данных — только на отдельном `*.test` сайте. Docker использует проект `albadr-tests` и игнорируемый `.local-tests`. Не запускать тесты на рабочем сайте школы и не обращаться к реальным платежам/SMS/календарям.
